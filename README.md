# 絵画世界美術館(仮)

美術館の中で絵画に近づくと、その絵の中の世界に入り込める一人称視点の3Dプロトタイプです。各世界で見つけた宝物を持ち帰り、別の世界の祭壇に捧げることで、少しずつ美術館全体に変化が起きていきます。

ブラウザだけで動作し、外部の画像・音声ファイルは一切使用していません。絵画のテクスチャ・地形・BGM・効果音はすべてコード上で(Canvas 2D と Web Audio API を使って)その場で生成しています。

## 遊び方

```bash
cd museum-portal
python -m http.server 8765
```

ブラウザで `http://localhost:8765` を開いてください(ES モジュールを使っているため、`index.html` を直接開くのではなく、ローカルサーバー経由で開く必要があります)。

### 操作

| キー | 動作 |
|---|---|
| `W` `A` `S` `D` | 移動 |
| マウス | 視点操作 |
| `E` | 調べる・拾う・祭壇に捧げる |
| `I` | 図鑑(コレクション画面)を開閉 |
| `M` | BGM のオン/オフ切替 |
| `Esc` | マウスロックを一時解除 |

## 主な要素

- **8つの空間**: 星月夜・灼熱の砂丘・深海・霧森・紅蓮・迷宮の6つの絵画世界(それぞれ固有の宝物と固有のギミックあり)、加えて隠し部屋の「幻の間」と、全クリア後にのみ現れる「祝福の間」
- **世界ごとのギミック**: 星月夜=足を踏み外すと戻される光の道、深海=渦潮、砂丘=蜃気楼、霧森=視界を塞ぐ深い霧、紅蓮=定期的な噴石の衝撃波、迷宮=手続き生成される本格的な迷路(壁に当たり判定あり)
- **世界間の謎解き**: 台座に置いた宝物を持ち上げ、別の世界の祭壇に捧げると、その世界のギミックが永久に和らぐ。どの宝物がどの祭壇を求めているかはページを開くたびにランダムに入れ替わり、祭壇の碑文(ヒント)を頼りに推理する
- **スコア・タイムアタック**: 経過タイムと得点を計測し、全ての祭壇を捧げ終えると結果画面が表示される。ハイスコアはこの端末に保存され、進行状況(集めたアイテムなど)は毎回リセットされるので何度でも挑戦できる
- **図鑑**: `I` キーでいつでも開ける収集記録画面。集めた宝物・祭壇の記録・これまでの出来事を振り返れる

## 技術構成

- **Three.js**(CDN 経由で importmap 読み込み、ビルドステップなし)
- Vanilla JavaScript / HTML / CSS のみ
- 画像・音声アセットは一切なし(テクスチャは Canvas 2D、BGM・効果音は Web Audio API でその場合成)
- `localStorage` にはハイスコアと BGM のミュート設定のみ保存(プレイ進行は保存しない設計)

## ファイル構成

```
museum-portal/
├── index.html          # エントリーポイント、HUD・モーダルの DOM
├── main.js             # 薄いオーケストレーター(イベント配線 + animate ループ)
├── style.css           # HUD・モーダルのスタイル
└── js/
    ├── config.js       # 定数・各絵画世界のデータ・祭壇の謎解きロジック
    ├── mazeGenerator.js# 迷宮の手続き生成 + 経路探索
    ├── textures.js      # Canvas 2D によるテクスチャ・アイテム形状の生成
    ├── audio.js         # Web Audio API による効果音・BGM
    ├── sceneSetup.js    # Three.js のシーン・カメラ・PointerLockControls
    ├── ui.js            # DOM 表示のみを担当する薄いプレゼンテーション層
    ├── worldBuilders.js # ギャラリーと各絵画世界の 3D オブジェクト構築
    ├── state.js         # ゲームの状態(進行・所持品・祭壇・スコア等)と画面遷移
    └── movement.js      # 移動処理と各世界固有のギミック(渦潮・迷路当たり判定等)
```

## 開発について

このプロジェクトは、Claude(Anthropic の AI アシスタント)との対話を通じて反復的に企画・実装されました。作者が方向性やフィードバック(「もっとミステリー要素を」「BGMを明るく」など)を出し、Claude がその都度コードを実装し、スクリーンショットや内部ロジックの直接実行によって動作を検証する、という進め方で作られています。
